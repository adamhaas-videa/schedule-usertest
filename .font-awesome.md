# Font Awesome Configuration

Detected by the Font Awesome agent tools. Commit this file so the whole team benefits.

## Integration

- **Method:** Self-hosted **Web Font**, imported from `src/index.css`. No CDN, no runtime script.
- **Version:** Pro 7.2.0
- **License:** Pro (Commercial) — `src/assets/fontawesome/LICENSE.txt`
- **Assets (in `src/assets/fontawesome/`):**
  - `css/fontawesome.min.css` — core: base `.fa` classes + all icon-name→glyph mappings
  - `css/regular.min.css` — `@font-face` (weight 400) + `.fa-regular`/`.far` selectors
  - `css/solid.min.css` — `@font-face` (weight 900) + `.fa-solid`/`.fas` selectors
  - `webfonts/fa-regular-400.woff2`, `webfonts/fa-solid-900.woff2`
- **Families shipped:** classic **regular** and **solid** only — the only two weights used in source (`fa-regular` ×47, `fa-solid` ×7). Vite bundles + content-hashes the woff2 files via the `url()` refs in the `@font-face` rules.

### Adding another family/weight

Source currently uses no light/thin/duotone/sharp/brands icons. To add one, copy that family's `<family>.min.css` and matching `fa-*.woff2` from a Pro Web kit download into `css/` and `webfonts/`, then add an `@import` line in `src/index.css`. (Duotone/sharp-duotone need their own CSS — they render two layers via `::before`/`::after`.)

### History

Previously loaded via the Pro **Kit embed script** (`kit.fontawesome.com/f165c6ea78.js`) in **SVG+JS** mode. That mode rewrote the DOM at runtime and fought React's reconciliation, causing icon **blinking** and **missing icons**. Switching to a self-hosted Web Font removed the CDN dependency and the DOM mutation entirely. The kit (`f165c6ea78`, allowed-domains list at https://fontawesome.com/kits/f165c6ea78/) is no longer referenced by the app.

## Defaults

- **Style:** `regular` (every existing usage in this codebase is `fa-regular fa-*`)
- **Family:** `classic`

## Import Pattern

Icons are rendered as plain `<i>` elements with Font Awesome classes.

```tsx
<i className="fa-regular fa-calendar-days" aria-hidden />
```

No React component (`<FontAwesomeIcon>`) is used or needed. Do not install `@fortawesome/*` npm packages – it would duplicate the kit and require an `FA_PACKAGE_TOKEN`.

## Rendering technology: Web Font (no SVG+JS)

This is a React SPA, and Web Font is the React-safe rendering mode. Each
`<i className="fa-...">` is rendered via a CSS `::before` glyph — there is **no
DOM mutation and no MutationObserver**, so React fully owns every `<i>`. The old
SVG+JS mode (which rewrote the DOM at runtime) caused icon blinking and missing
icons by racing React's reconciliation; self-hosting the Web Font removed that
class of bug entirely. Do **not** reintroduce the SVG+JS kit script.

Sizing note: the glyph is sized by `font-size`, not by the box. Icons styled
only with `w-* h-*` Tailwind utilities (e.g. `w-4 h-4`) should also carry a
`text-*` size (e.g. `text-base`, `text-sm`, `text-[10px]`) to control the glyph
size. Most call sites already do this; a handful still use `w-*/h-*` alone
(`fa-images w-4 h-4`, `fa-xmark w-3.5 h-3.5`) and render at the inherited
font-size — add a `text-*` if one looks off.

## Conventions

- All call sites use `<i className="fa-regular fa-*" aria-hidden />`. New icons should follow the same pattern. Use a different weight prefix (`fa-solid`, `fa-light`, `fa-thin`, `fa-duotone`, `fa-sharp fa-regular`, etc.) only when there is a deliberate visual reason.
- Add the `aria-hidden` attribute when the icon is purely decorative, and pair an `aria-label` (or visible label) on the parent control when the icon carries meaning on its own.
- Sidebar icons use `text-base w-5 text-center shrink-0` for sizing/layout – see `src/components/layout/Sidebar.tsx`.

## Bundle size / subsetting

The self-hosted `css/fontawesome.min.css` ships the full icon-name→glyph mapping
table (~144 KB, ~50 KB gzipped) regardless of how many icons are used, but the
actual glyph data lives in the woff2 files — and only the two families imported
(`fa-regular-400.woff2`, `fa-solid-900.woff2`) ship. The woff2 files are the
complete Pro sets for those weights (not subset). If bundle size becomes a
concern, generate subset woff2 files containing only the ~30 glyphs in use.

Prefer full literal class strings (`fa-regular fa-calendar-days`) over dynamic
concatenation (`` `fa-${name}` ``) so usage stays greppable for any future
subsetting step.

## Notes for future maintainers

- Fonts are bundled and content-hashed by Vite via the `url(../webfonts/…)`
  refs in `regular.min.css` / `solid.min.css`. Keep the CSS and webfonts in the
  same relative layout (`css/` beside `webfonts/`) or those paths break.
- No CDN / kit script is used, so there is no allowed-domains list to maintain
  and nothing to break on a new preview hostname.
