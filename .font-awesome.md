## Defaults

- **Style:** `regular` (every existing usage in this codebase is `fa-regular fa-*`)
- **Family:** `classic`

## Import Pattern

Icons are rendered as plain `<i>` elements with Font Awesome classes.

```tsx
<i className="fa-regular fa-calendar-days" aria-hidden />
```

No React component (`<FontAwesomeIcon>`) is used or needed. Do not install `@fortawesome/*` npm packages – it would duplicate the kit and require an `FA_PACKAGE_TOKEN`.

## Rendering technology: prefer Web Font over SVG+JS (IMPORTANT for React)

This is a React SPA. The kit's **SVG+JS** technology rewrites the DOM at runtime
(via a `MutationObserver` it replaces/nests an `<svg>` inside each `<i>`). That
mechanism fights React's reconciliation and causes the two classic symptoms:

- **Blinking** – SVG+JS defaults to `mutateApproach: "async"`, deferring icon
  injection to `requestAnimationFrame`, so each mount/re-render shows an empty
  `<i>` for a frame before the icon pops in. StrictMode double-mounts and
  `className` swaps (e.g. the sidebar collapse chevron) make this repeat.
- **Missing icons** – on unmount/remount or `className` change, the observer
  races React; the new `<i>` can be left without its injected `<svg>`.

### Permanent fix (recommended): switch the kit to Web Font

In the kit dashboard at https://fontawesome.com/kits/f165c6ea78/settings set
**Technology → Web Font**. The same `kit.fontawesome.com/f165c6ea78.js` script
then ships CSS + webfonts and renders each `<i>` via a `::before` glyph. There is
**no DOM mutation and no MutationObserver**, so React fully owns every `<i>` and
the blinking/missing-icon problems disappear. No code change is required to flip
this – the `window.FontAwesomeConfig` SVG options in `index.html` are simply
ignored in Web Font mode.

Sizing note for Web Font mode: the glyph is sized by `font-size`, not by the
box. Icons styled only with `w-* h-*` Tailwind utilities (e.g. `w-4 h-4`) should
use a `text-*` size (e.g. `text-base`, `text-sm`, `text-[10px]`) to control the
glyph size. Most call sites already do this.

### Interim mitigation (already applied, while still on SVG+JS)

`index.html` sets `autoReplaceSvg: "nest"`, `observeMutations: true`,
`mutateApproach: "sync"`, and `keepOriginalSource: false`. `sync` removes the
`requestAnimationFrame` flash and is the biggest blink reducer available without
leaving SVG+JS. These options are no-ops once the kit is switched to Web Font.

## Conventions

- All call sites use `<i className="fa-regular fa-*" aria-hidden />`. New icons should follow the same pattern. Use a different weight prefix (`fa-solid`, `fa-light`, `fa-thin`, `fa-duotone`, `fa-sharp fa-regular`, etc.) only when there is a deliberate visual reason.
- Add the `aria-hidden` attribute when the icon is purely decorative, and pair an `aria-label` (or visible label) on the parent control when the icon carries meaning on its own.
- Sidebar icons use `text-base w-5 text-center shrink-0` for sizing/layout – see `src/components/layout/Sidebar.tsx`.

## Subsetting

The kit auto-subsets to icons referenced in source files at build time on the Font Awesome CDN side. If an icon stops rendering after deploy, confirm the class name appears literally somewhere in the built output (dynamic concatenation like `` `fa-${name}` `` can be missed by the scanner – prefer the full literal class string).
